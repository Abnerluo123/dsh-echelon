# dsh-model-router

为 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 提供**挡位式模型路由**的插件。

模型选择器里只留下你自己定义的挡位（比如「日常」「攻坚」「便宜」）。选中一个挡位，请求就按你排好的顺序依次调用真实模型；某个模型重试之后仍然失败，自动换下一个。挡位背后是哪个模型、有多少个备用，只有你配置的时候需要关心一次。

## 它解决什么

装了多个厂商/渠道插件之后，模型选择器会变成几十上百个条目：`deepseek-ai/deepseek-v4.1-flash`、`z-ai/glm-5.3-flash`、`Qwen3.8-Max · x0.5→x0.2`……挑模型变成查表。而单个渠道的限流、额度墙、地区拦截、上游 5xx 又会直接把这一轮对话打死，哪怕另外五六条通道正闲着。

装上这个插件之后：

- 菜单里只有你命名的那几个挡位；
- 每个挡位是一条有序链，链上每个模型可以有自己的**重试次数**和**超时**；
- 失败自动降级，用户看不到失败的尝试，也看不到半截回答；
- 原来的几百个模型可以全部隐藏，需要时随时切回来。

## 快速开始

1. 设置 → **模型路由**，点「新增挡位」，命名（例如「日常」）。
2. 在挡位里点「添加模型」，从目录里挑真实模型；第一个就是首选。
3. 调整顺序、每个成员的重试次数与超时。
4. 「模型选择器的显示」选 **只显示挡位**（推荐）。
5. 保存。几秒内模型选择器刷新，只剩下你的挡位。

之后想换「日常」用哪个模型，只改这个挡位的成员顺序，不用再去菜单里找模型名。

## 概念

| 概念 | 含义 |
|---|---|
| **挡位（tier）** | 暴露给模型选择器的一个名字，背后是一条有序链。挡位 id 由名称派生，改大小写或标点仍是同一个 id。 |
| **成员（member）** | 一个 `<来源>/<模型>` 组合，加上它自己的重试次数、超时、上下文长度、输出上限、思考强度。 |
| **重试次数** | 这个成员失败后**再试几次**才换下一个。`0` 表示不重试，`1`（默认）表示最多试两次。 |
| **超时** | 这么久没有收到**任何数据**就放弃这次尝试、换下一个。`0` 表示不限制。 |
| **上下文长度 / 最大输出** | 留空 = 用模型自己上报的值；填了会覆盖上报值。 |
| **思考强度** | 留空 = 跟随会话里选的那一档；选了具体档位，这个成员只用那一档。 |
| **显示模式** | 只显示挡位 / 只隐藏我勾选的 / 全部显示。 |

成员的这几项设置默认折叠在「详情」里，折叠时摘要仍显示当前值，所以不用展开也知道这个成员设成了什么。

挡位和成员都可以设「思考强度」与「上下文长度」：**成员自己的设置优先**，没设就用挡位的，都没设就跟随模型上报值/会话选择。所以常见场景不用逐个成员去设——改一次挡位默认值，整条链跟着变。

## 行为细节

**按顺序调用，第一个成功就停。** 链上第一个产出可见内容的成员赢得这一轮，后面的成员完全不会被调用，因此不会产生多余的费用。

**失败会继续走链。** 哪些失败值得在同一个模型上重试，由失败码决定：

| 失败码 | 同模型重试 |
|---|---|
| `RATE_LIMIT` `SERVER` `TIMEOUT` `TRANSPORT` `EMPTY_RESPONSE` `UNKNOWN` | 是 |
| `AUTH` `QUOTA` `INVALID_REQUEST` 等确定性失败 | 否，直接换下一个 |
| `ABORTED` `CONTEXT_WINDOW_EXCEEDED` | 结束这一轮，不换 |

确定性失败（例如密钥失效）重试只会在同一个坑里多等几秒，但**换一个成员仍可能成功**，所以链继续走。

**半截回答不会泄漏。** 成员的输出会先缓冲，直到出现读者真正会看到的内容（正文或工具调用）才提交。也就是说：某个模型先输出了思考过程然后断流，这个尝试会被静默丢弃，对话里只出现下一个模型的完整回答。只输出思考不算成功。

**一轮只结束一次。** 每条路径都以恰好一个结束块收尾：要么真实回答，要么一个错误——错误里列出试过哪些成员、各自为什么失败。

**上下文窗口按需路由，而不是取交集。** 挡位向 DSH 上报的是成员里**最大**的窗口，所以一个 1M 模型放进挡位后，大请求不会被 300K 的同伴压住。实际派发时插件会估算这次请求的输入大小，跳过装不下的成员，把请求交给链上第一个装得下的；被跳过的成员会记在调用日志里（`CONTEXT_TOO_SMALL`）。

代价与取舍：

- 估算用的是 DSH 自己的 `tokenMeter`（与压缩、占用显示同一个数），拿不到时退回 4 字符/token 的固定启发式。两者都是**估算**，会额外留出输出空间和 2% 余量。
- 如果整条链都装不下，会尝试窗口最大的那个成员——让上游给出真实报错，比本地凭空拒绝更有用。
- 成员没有上报窗口时**不会被跳过**：没有证据表明它小。

## 调用日志

设置页的第二个页签是**调用日志**，每次请求一条记录，答的是「这一轮到底是哪个模型干的」——这件事在对话记录里看不见，因为挡位把成员藏起来了。

每条记录包含：

- 最终**由哪个模型作答**、挡位名、耗时；
- 依次试过哪些成员、第几次尝试、各自**为什么被换掉**（失败码与原因）；
- 有没有重试、是重试后成功还是直接降级；
- 成功时的 token 用量（模型上报时才有）。

日志**只存在内存里**，重启即清空，也不写任何文件。默认保留 200 条，可在「高级」里改（20–2000）。可以随时关闭记录。

> 为什么不做成落盘日志：这是排障用的即时视图，不是审计。落盘会带来轮转、隐私和体积问题，而排障时你真正想要的是「刚才那三轮分别发生了什么」。

## 隐藏模型

「只显示挡位」会隐藏其它所有真实模型，模型选择器里只剩你的挡位。

要点：

- **隐藏只影响呈现与选择，不影响派发。** 被隐藏的模型仍然可以被挡位调用——挡位走的是直接派发路径，不查目录。这正是「只显示挡位」能成立的前提。
- **隐藏的模型也不能再被手动选中**，包括之前保存过它的会话。这是隐藏的本意。
- **没有可用成员时不会隐藏。** 如果一个挡位都派发不了（例如刚装好还没配成员），插件会自动放开隐藏，否则模型选择器会变成空的、你也进不去设置修正它。
- 隐藏是即时生效的：保存后几秒内菜单刷新。

## 与其它插件共存

插件只注册一个自己的 provider 路由 `model-router`，**不改任何别人的路由**。

因此挡位的成员可以是任何已注册路由上的模型，包括其它插件的路由：

- `dsh-our-free-model` 的免费车道与组合（`our-free-model/...`）；
- `dsh-model-fusion` 的 `dsh-model-fusion/auto`；
- `dsh-llm-pi-ai` 里你自己声明的中转站。

一个常见用法是把 Fusion 的 `auto` 放进挡位链里当首选，再用一两个便宜模型兜底——Fusion 需要一个便宜 Sidekick，链路降级正好补上它挂掉的那一轮。

## 配置文件

设置在 `$DSH_HOME/model-router/settings.json`（Windows 默认 `C:\Users\<你>\.dsh\model-router\settings.json`）。可以手改，改动会在下一次请求时生效，不用重启。

```json
{
  "version": 2,
  "exposure": "tiers",
  "defaultIdleTimeoutMs": 90000,
  "showTierDescriptions": true,
  "logRequests": true,
  "logLimit": 200,
  "tiers": [
    {
      "id": "daily",
      "name": "日常",
      "enabled": true,
      "order": 0,
      "reasoningEffort": "high",
      "contextWindow": 200000,
      "members": [
        { "provider": "my-gateway", "model": "fast-model", "attempts": 1, "idleTimeoutMs": 90000, "enabled": true },
        { "provider": "my-gateway", "model": "solid-model", "attempts": 2, "idleTimeoutMs": 60000, "enabled": true,
          "reasoningEffort": "max", "contextWindow": 128000, "maxTokens": 32768 }
      ]
    }
  ],
  "hide": [{ "target": "other-gateway/some-model", "enabled": true }]
}
```

文件是容错的：字段缺失、类型不对、数值越界都会被规范化；整份文件损坏会退回默认值并在设置页说明原因。写入是「先写临时文件再重命名」，所以中途失败不会留下半份配置。

## 安装

**从插件市场安装**（推荐）：插件 → 插件市场，搜索 `dsh-model-router`。

**从本地目录安装**：在 DSH 的 插件 → 已安装 → 添加插件 里填绝对路径；或者

```sh
dsh plugin --profile <profile> add /absolute/path/to/dsh-model-router
```

装完重启 `dsh`，刷新页面后设置里会出现 **模型路由**。

## 开发

```sh
node --test test/               # 全部测试
node scripts/verify-profile.mjs # 检查当前 profile 能否加载本插件
```

测试不需要网络，也不需要 DSH 运行时。`test/integration.test.js` 会在本机存在 DSH 应用包时，用**真实的** `LlmRuntime` 跑一遍注册、派发、隐藏与降级；找不到时自动跳过。

源码结构：

| 文件 | 职责 |
|---|---|
| `index.js` | Host 入口：注册路由、挂载目录过滤、挂载设置 API |
| `src/config.js` | 纯配置逻辑：规范化、链展开、重试判定 |
| `src/adapter.js` | 适配器：按链派发、缓冲、重试、降级、写日志 |
| `src/catalog.js` | 目录过滤：把模型从选择器里隐藏 |
| `src/log.js` | 内存调用日志：有界、按次追加、不落盘 |
| `src/tokens.js` | Request-size estimation (DSH token meter, documented fallback) and context-fit ordering |
| `src/http.js` | 设置 / 日志 API 与同源信任检查 |
| `src/store.js` | 原子写入 + 按 mtime 失效的缓存 |
| `client.js` | 浏览器半身：设置页 + 调用日志页 |

## 已知限制

- **隐藏依赖包装 `llm.listModels`。** DSH 没有目录过滤钩子，所以插件包装了服务实例上的这个公开只读方法。绕过它直接读适配器的代码不会被过滤。
- **调用日志只存内存。** 重启即清空；这是排障视图，不是审计记录。
- **热重载会重置路由器的内存状态。** 配置本身在磁盘上，不受影响；日志随进程消失。
- **`ABORTED` 与 `CONTEXT_WINDOW_EXCEEDED` 不降级。** 前者是你自己取消的，后者换个模型也装不下这段上下文；降级只会掩盖真正的问题。
- **一轮最多 64 次尝试**，防止某个配置把自己转成死循环。
